Greia aims to support older netbooks and PCs alongside Raspberry Pi keyboard computers and other suitable hardware. A download will only be enabled when a real file and a named tested scope exist.

⌨LEGACY & MODERN X86

Netbooks & PCs

From first-generation netbooks onward. The early Acer Aspire One is the demanding low-resource reference, with broader PC support to be named per release.

  • Whole-machine Greia installation
  • Child Shell instead of a desktop
  • Exact models to be listed with each image
⌨ARM / KEYBOARD COMPUTER

Raspberry Pi 400

A practical setup: connect a display and give the child the computer built into the keyboard. The Pi 400 is a first-class Greia target.

  • Greia child experience on ARM
  • Compact physical setup
  • Device-specific graphics and input gate
⌨ARM / KEYBOARD COMPUTER

Raspberry Pi 500

The same keyboard-computer simplicity on newer hardware. Greia aims to keep profiles, Activities, Parent controls and child navigation consistent.

  • One Greia across CPU families
  • Portable child profile data
  • Device-specific release testing

An installer replaces or changes the target computer's operating system. Future release instructions will identify eligible devices, backup steps, image verification and the graphical installation path before offering an active download.

WHAT WILL MAKE A DOWNLOAD REAL

Files, checks,
and a clear scope.

01

Named hardware

Each image will state exactly which devices and input/graphics paths passed its release gate.

02

Verified artifact

The file, checksum, build identity and installation instructions must refer to the same tested release.

03

Family-ready route

Install, recovery, updates, backup and Parent connection must be understandable without a Linux maintenance shell.
