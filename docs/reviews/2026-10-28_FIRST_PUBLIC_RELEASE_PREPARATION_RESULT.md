## 5. Can the existing Git history become public safely?

**Not yet.** No real secret was found in either history. The OS history scan
found only literal private-key *header strings* used as negative fixtures in
`tests/test_parent_tls.py` and `tests/test_rc_image_contract.py`; they are not
credentials. The Parents history contains no detected key/token material.

However, the existing Greia history contains the macOS System Voice
recordings across many commits. Making that history public publishes the
restricted media even if they are removed from HEAD. Options are:

1. obtain Apple permission or a competent legal grant;
2. replace the recordings and then publish a **new rights-cleared snapshot
   repository** (history of the old repository stays private), or rewrite
   shared history with explicit owner authorization;
3. keep the existing repository private until replacement audio is accepted.

No history rewrite or mass deletion was performed.
