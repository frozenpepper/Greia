## 0. Bottom line

1. **The build is expected to fail the installed-size gate.** `build/build-image.sh:217` hard-fails at ≥1,000 MiB accounted. The last measured dev image used 984 MiB (2026-10-01, `101e332a:HANDOVER.md` §8e). Since then the installed Activity tree grew from 102.2 to 187.9 MiB (`git ls-tree`, `439a9060` → HEAD) and the installed assets from 27.2 to 35.2 MiB. The new bytecode prefix adds about 34 MB (Acer sweep, 44aa49ed). **Projection: about 1,110 MiB, so FAIL** (estimate, UNPROVEN). About 73.5 MiB of that growth is staged ES/FR audio, which no user can select. Another 3.1 MiB is 2,595 `.receipt.json` files, roughly 10 MiB on 4 KiB blocks.
2. **"No text at boot" conflicts with six enforcement points.** Developer images enforce `console=tty1 panic=0 systemd.show_status=true` in `src/greia_platform/boot_contract.py`, `build/overlay/etc/grub.d/10_greia_appliance`, `build/live-syslinux/syslinux.cfg.in`, `tools/verify-live-usb.sh:161-169`, `tools/verify-development-installer.sh:207-211` and `tools/verify-development-target-image.sh:134-138`. A partial change either fails the build late or silently removes the only boot diagnostics. The target journal is `Storage=volatile` (`build/overlay/etc/systemd/journald.conf.d/10-greia-bounds.conf`), so nothing else would survive a boot loop.
3. **One tranche crosses a proven boot boundary several ways at once.** Today's work brings the installer UI redesign, the boot animation in the installer and installed OS, console silencing and the Parent changes. That is exactly the pattern the 2026-08-20 regression review forbids (§9: presentation polish never crosses a proven boot boundary inside an unrelated tranche).
4. **The installed system has had exactly one end-to-end attempt (2026-10-07), and it boot-looped.** The repairs from 2026-10-07 to 10-17 (profile modes, B5, observer gating, display descriptor, bytecode prefix, SDL framebuffer hint, launch card, mixer lease) have **never been in a built image**. That is 34 commits under `build/` and `src/greia_installer` since `64103e48`. The third-generation loop teardown has only passed its fixture, never a full build+flash.
