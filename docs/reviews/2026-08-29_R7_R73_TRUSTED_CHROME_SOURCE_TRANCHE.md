## Progress entry to append to the active plan

### 2026-08-29 — R7.3 trusted Home source tranche (execution/physical acceptance pending)

- **Implemented:** began R7.3 behind the existing runtime-neutral `SystemChromeCoordinator` rather than inventing another graphics layer. Added `LegacyXSystemChromeBackend`/`CtypesLegacyXChromeBridge` as a strictly provisional migration adapter: one launcher-process X11 window limited to `ActivitySystemChromeLayout.protected_region`, mapped above the Activity after READY, event-driven drawing on show/expose, nonblocking protected pointer polling, no Activity pixel copies, no second Pygame renderer/process and no full-screen composition layer. Added `TrustedChromeActivitySupervisor` to bind exact chrome leases to the authoritative Activity session, route Home through the existing graceful/forced lifecycle, and tear chrome down through normal/crash/failed-launch display cleanup. Installed `GreiaChildShell` now composes the trusted chrome coordinator; the X-session fallback was changed from plain `greia_launcher.presentation` to `greia_launcher.trusted_presentation` so fallback cannot become an unprotected Activity route. Corrected a separate R7.2 integration regression where rich `presentation.py` still imported the removed `_set_x11_input_focus`; it now uses the same composition-owned `ShellWindowController` hook as the generic launcher. Hardened `SystemChromeCoordinator.prepare()` so a backend prepare failure fails that launch but performs one bounded rollback; successful cleanup returns to `HIDDEN` so a transient failure does not poison every later Activity, while failed rollback remains `FAILED`. Added a deliberately non-cooperative developer fixture `tests/fixtures/activities/r7_noncooperative_chrome/` that fills the whole SDL surface, draws no Home, ignores local input and never checks the graceful STOP marker, allowing the physical gate to prove platform-owned Home plus bounded forced return independently of Activity cooperation.
- **Tests/evidence:** source regression files are committed for coordinator lifecycle/recovery, Legacy-X backend semantics, trusted-supervisor integration, installed primary/fallback composition, hostile fixture behavior, R7.2 shell-window containment and Activity device authority. Added exact execution protocol `docs/testing/2026-08-29_R7_R73_TRUSTED_SYSTEM_CHROME_SOURCE_AND_ACER_ACCEPTANCE.md`, requiring focused source suites, repository backend audit with `blockers=0`, `make verify`, same-SHA R7.2 Acer prerequisite evidence, Writing/Painting trusted Home, hostile fullscreen Home/forced-return proof, 10/10 hostile cycles, crash cleanup and exact-device CPU/RSS/latency/render sanity. **No current-head focused-suite PASS, `make verify` PASS, native Xlib execution PASS or physical Acer R7.3 PASS is claimed in this connector-only tranche.**
- **Decisions:** ADR 0014 remains authoritative: X11 is not target Greia architecture. The Legacy-X chrome window is migration evidence for the platform structure, first-party/non-cooperative lifecycle behavior and performance shape; shared X11 cannot certify final hostile-third-party isolation because a sufficiently privileged X client may interfere with sibling windows. Final architecture remains DRM/KMS-centered direct/appliance graphics with a minimal compositor allowed where measurement shows it is the thinnest practical trusted session path. R7.3 initially closes mandatory Home only; optional Back stays disabled until real launch-origin context is carried through the trusted boundary. Performance remains a correctness contract: preserve direct SDL Activity rendering, Painting/Writing high-rate paths, dirty/invalidation rendering and backend-private fast paths; do not turn chrome into a framebuffer proxy or permanent full-screen compositor tax.
